# ADR-006 :: Two editions from one codebase

Last updated: `2026.10.02`

> Quoth ships twice from the same sources: a free, open-source direct download with every in-window feature, and a sandboxed Mac App Store edition that keeps to Apple's rules. Everything that differs is decided in `Support/Edition.swift`.

## 1. Decision

- **Direct edition.** The Swift package (`Package.swift`, `scripts/build-app.sh`), signed with a Developer ID and notarized, free and MIT-licensed. Accessibility covers the hotkey, pasting with ⌘V and reading the focused field, so it can refuse password fields, notice focus moving, and space text against what is before the cursor. It updates with Sparkle and has the `quoth` command (`setup`, `doctor`, `models`, `install`).
- **App Store edition.** An Xcode project generated by xcodegen from `project.yml`, compiling the same `Sources/QuothCore` with the `APPSTORE` flag and its own entry point (`AppStore/main.swift`). Sandboxed, with only audio input and outgoing network (model downloads). $1.99.
  - The hotkey's listen-only tap needs **Input Monitoring** instead of Accessibility.
  - Pasting needs its own optional grant (`CGRequestPostEventAccess`). Without it, each transcript is copied and the pill says "press ⌘V"; a locked dictation is copied once at the end instead of typed live. `Edition.allowsAutoPaste = false` makes the build copy-only, should App Review rule out auto-paste (guideline 2.4.5).
  - The focused field can't be read: focus checks compare the frontmost app, and secure input (which macOS turns on for password fields) stands in for the password-field check.
  - No Sparkle, no command line, no doctor checks (`project.yml` leaves their files out).
- **Identity.** Direct development builds are `local.quoth`; the App Store build is `com.victorshammas.quoth`, team `JPP8RN6BJB`.

## 2. Rationale

What makes in-window dictation good (reading the field, posting events freely) is exactly what the sandbox forbids, so one build can't be both the best tool and an App Store app. Two builds from one codebase keep every shared feature in both, and keep the differences reviewable in one file instead of `#if` throughout.

## 3. Design implications

- Rule: code asks `Edition`, `HotkeyAccess` or `PasteAccess`; only those test `APPSTORE`, apart from leaving out the Sparkle and command-line call sites.
- Every feature must work in the clipboard-only App Store build, or degrade to it.
- The App Store build compiles no Accessibility calls at all: with `Edition.readsFocusedField` a constant false, the compiler strips them.

## 4. When to revisit

- If App Review rejects auto-paste: ship copy-only and say so in the listing.
- If Apple adds a sandbox-safe way to insert text into other apps.
